[[http_verbs]]
== HTTP verbs

Spexregister Server tries to adhere as closely as possible to standard HTTP and REST conventions in its
use of HTTP verbs.

|===
| Verb | Usage

| `GET`
| Used to retrieve a resource

| `POST`
| Used to create a new resource

| `PATCH`
| Used to update an existing resource, including partial updates

| `DELETE`
| Used to delete an existing resource
|===

[[http_status_codes]]
== HTTP status codes

Spexregister Server tries to adhere as closely as possible to standard HTTP and REST conventions in its
use of HTTP status codes.

|===
| Status code | Usage

| `200 OK`
| The request completed successfully.

| `201 Created`
| A new resource has been created successfully. The resource's URI is available from the response's
`Location` header

| `204 No Content`
| An update/delete to an existing resource has been applied successfully

| `400 Bad Request`
| The request was malformed.

| `404 Not Found`
| The requested resource did not exist.

| `409 Conflict`
| The request could not be completed due to already existing resource.

| `500 Internal Server Error`
| A fatal error has occurred.
|===

[[hypermedia]]
== Hypermedia

Spexregister Server uses hypermedia and resources include links to other resources in their
responses. Responses are in https://github.com/mikekelly/hal_specification[Hypertext
Application Language (HAL)] format. Links can be found beneath the `_links` key. Users of
the API should not create URIs themselves, instead they should use the above-described
links to navigate from resource to resource.

[[filtering]]
== Filtering

When retrieving resources, it is possible to apply filtering. Note that it does not
apply to all resources.

The available operations are:

* Simple operations
** Equality: represented by colon (:)
** Negation: represented by exclamation mark (!)
** Greater than: represented by (>)
** Less than: represented by (<)
** Like: represented by tilde (~)
* Complex operations
** Starts with: represented by (:prefix*)
** Ends with: represented by (:*suffix)
** Contains: represented by (:*substring*)

The syntax is:

``<attribute><operation><value><optional operation>``

Example: ``nickName:colg*``

Filtering on multiple attributes can be done by joining with ``AND`` or ``OR``, very much
like the WHERE clause in SQL statements. To group clauses, use ``( `` and `` )`` (note the
trailing and leading whitespaces).

Example: ``firstName:anders OR ( nickName:colgate AND lastName:jacobsson )``
