[[prerequisites]]
== Prerequisites

You need to have the following installed to run Spexregister Server:

* Docker
** Version 29.0.1 is verified to work

You also need the following if you are to do development in Spexregister Server:

* Git
* Java
** Version 25 is required, later versions might work as well
* An IDE of your choice

[[cloning_the_repository]]
== Cloning the repository

Clone the Git repository:

[source,bash]
----
$ git clone https://github.com/bloomper/spexregister-server
----

[[setup]]
== Setup

Keycloak, Mailpit and Caddy, which FGV's applications share, run in the local stack of
https://github.com/bloomper/fgv-infra-deploy[fgv-infra-deploy].
Check it out next to this repository and set it up as its README describes under _Local development_.
It creates the Docker network ``fgv-local``, which this repository's ``docker-compose.yaml`` joins.

There are some configuration parameters that need to be set before Spexregister Server can be started.
Each parameter is a file under ``.docker/secrets``, containing only the value.
The files are in git with the placeholder ``CHANGE_ME``, as are the directories that ``docker-compose.yaml`` mounts
(kept by ``.gitkeep``). Replace each placeholder, without a trailing newline, e.g.
``printf '%s' 'verysecret' > .docker/secrets/SPEXREGISTER_MYSQL_ROOT_PASSWORD``, and tell git to leave your values
alone so they are never committed:

[source,bash]
----
$ git update-index --skip-worktree .docker/secrets/*
----

To see a changed placeholder after a pull, undo it with ``git update-index --no-skip-worktree .docker/secrets/*``.

|===
|Parameter|Purpose|Comment|Example value

|SPEXREGISTER_MYSQL_ROOT_PASSWORD|The password for the root user of Spexregister Server's database||verysecret
|SPEXREGISTER_MYSQL_USER_PASSWORD|The password for the user of Spexregister Server's database||secret
|API_KEYCLOAK_ADMIN_CLIENT_SECRET|The client secret of Spexregister Server's Keycloak admin client|Must match the value in ``realm/fgv.json`` in https://github.com/bloomper/fgv-keycloak[fgv-keycloak], search for ``fgv-admin`` (if not changed in ``.env``) and pick the value for ``secret`` in the same section|tPE9jFHcjpvKT64v6fpZyvUbbRQI5P5Q
|API_SECRET_KEY|The key used for encrypting sensitive data|A 32 character long string that can contain alphanumeric characters and special characters|j4{}8@4{eRrz1athvM7C_*{7XM}NP=J3

|===

There are also configuration parameters in ``.env`` that can be tweaked if so desired but the default values will work just fine.

|===
|Parameter|Purpose|Default value

|SPEXREGISTER_MYSQL_DATABASE|The name of the database used by Spexregister Server|spexregister
|SPEXREGISTER_MYSQL_ROOT_USER|The root user of Spexregister Server's database|root
|SPEXREGISTER_MYSQL_USER|The user of Spexregister Server's database|spexregister
|API_KEYCLOAK_REALM|The Keycloak realm of Spexregister Server|fgv
|API_KEYCLOAK_ADMIN_CLIENT_ID|The Keycloak admin client id of Spexregister Server|fgv-admin
|API_KEYCLOAK_CLIENT_CLIENT_ID|The Keycloak client id of Spexregister Server|spexregister
|API_SEED_AUDIT_DATA|A flag determining whether to give every existing row a baseline revision at startup, which only happens while there are no revisions|false
|API_IMPORT_SAMPLE_DATA|A flag determining whether to import sample data or not|false

|===

Access tokens are only accepted from the Keycloak clients listed in ``SPEXREGISTER_SECURITY_AUTHORIZED_PARTIES``, which defaults to ``API_KEYCLOAK_CLIENT_CLIENT_ID``.
For Nyuppsättning's service account to be let in, the list must include ``fgv-revival-service``; ``docker-compose.yaml`` sets it to ``spexregister,fgv-revival-service``.

Add the following to `/etc/hosts` (or the Windows equivalent):

[source,bash]
----
###################################
#          Spexregister           #
###################################
127.0.0.1 auth.fgv.local.nu
127.0.0.1 api.register.fgv.local.nu
127.0.0.1 register.fgv.local.nu
127.0.0.1 mail.fgv.local.nu
----

[[run]]
== Run

You are now ready to get Spexregister Server up and running, after fgv-infra-deploy's local stack:

[source,bash]
----
$ docker compose -f ../fgv-infra-deploy/local/compose.yaml up -d
$ docker compose up -d
----

Keycloak, its realm, registration and Turnstile are described in fgv-infra-deploy's README.
The realm lets a locally running https://github.com/bloomper/spexregister-web[spexregister-web], i.e. ``npm run dev``, log in from ``SPEXREGISTER_URL`` in fgv-infra-deploy's ``local/.env``, which defaults to ``http://localhost:3000``.

``./scripts/configure-keycloak.sh`` allows Postman's callback URL in Keycloak (see <<testing_the_api>>).
It finds fgv-infra-deploy in ``../fgv-infra-deploy``, or where ``INFRA_DEPLOY`` points.

When the ``spexregister-api`` container isn't running, Caddy forwards ``https://api.register.fgv.local.nu:8443`` to port 8080 on the host, i.e. Spexregister Server started from the IDE or with ``./gradlew bootRun``.

The same setup for staging and production is in https://github.com/bloomper/spexregister-deploy[spexregister-deploy] and fgv-infra-deploy.

[[sample_data]]
== Sample data

If ``API_IMPORT_SAMPLE_DATA`` in ``.env`` is set to ``true``, sample data will be imported.
Sample data consists both of real data and random data but none of the data can be traced to real individuals, i.e. no personally identifiable information (PII).

[sidebar]
.NOTE
--
Any existing data and all users in Keycloak will be wiped out, at every start.
--

The import also creates the users listed under <<test_credentials>> in Keycloak, together with a number of random users.
The realm itself contains no users, so without sample data the first user has to register and be given roles in Keycloak's admin console.

[[keycloak]]
== Keycloak

[[keycloak_customization]]
=== Customization

In order to support passwords from the previous Spexregister generation, a custom password hashing provider has been implemented.
At first login, the password is re-hashed using the default password hashing provider.

The provider lives in https://github.com/bloomper/fgv-keycloak[fgv-keycloak], together with the other Keycloak providers, the realm and the theme.
That repository publishes the Docker image ``bloomper/fgv-keycloak``, which fgv-infra-deploy runs.

[[keycloak_administration]]
=== Administration UI

The administrative UI of Keycloak can be accessed at https://auth.fgv.local.nu:8443/auth.
The username is ``KEYCLOAK_ADMIN`` in fgv-infra-deploy's ``local/.env`` and the password is in its ``local/.docker/secrets/KEYCLOAK_ADMIN_PASSWORD``.

[[keycloak_setup]]
=== Setup

The realm is defined by ``realm/fgv.json`` in https://github.com/bloomper/fgv-keycloak[fgv-keycloak], whose README describes what it contains.
To change it, make the change in the administration UI, export it with _Realm settings -> Action -> Partial export_ and carry the change over to ``fgv.json`` by hand.
Keep the `+${...}+` placeholders, and keep realm keys and users out, apart from the service account of ``fgv-admin``.
Copy the result to ``src/integrationtest/resources/keycloak/fgv.json`` as well.

[[caddy]]
== Caddy

Caddy, in fgv-infra-deploy's local stack, is used as a web server in front of Keycloak and Spexregister Server and takes care of creating and assigning an SSL certificate.
However, since it is listening to local addresses, the certificate is not created by a proper CA (Certificate Authority).
It is therefore needed to import the root certificate to avoid browsers complaining about the certificate.

The root certificate can be found in fgv-infra-deploy's ``local/.docker/caddy/data/caddy/pki/authorities/local/root.crt``.
Import it into your OS's trust manager.

[[mailpit]]
== Mailpit

Mailpit (https://mailpit.axllent.org/), in fgv-infra-deploy's local stack, acts as the SMTP server when running locally.
It catches all emails sent by Keycloak and Spexregister Server, nothing is delivered to real recipients.

The caught emails can be viewed at https://mail.fgv.local.nu:8443 (or http://localhost:8025).

These are the emails sent:

|===
|Email|Sent by|Recipient

|Email verification|Keycloak|The registering user
|New user awaiting approval|Keycloak|``admin@fgv.local.nu``, can be changed by setting ``ADMIN_NOTIFICATION_RECIPIENTS`` in fgv-infra-deploy's ``local/.env``
|Account approved|Keycloak, when an administrator assigns the user a role|The approved user
|Removal request|Spexregister Server, when a user asks for their data to be removed|``admin@fgv.local.nu``, set by ``ADMIN_NOTIFICATION_RECIPIENTS`` in ``docker-compose.yaml``

|===

[[tests]]
== Tests

There are two types of tests:

* Unit tests, located under ``src/test``
* Integration tests, located under ``src/integrationtest``

Unit tests do not require any external dependencies, such as a database, and are therefore quicker to run.
An example of unit tests is API tests which are used to generate the REST API documentation.
Apart from API tests, unit tests are mostly only written for complex logic.

Integration tests start MySQL and Keycloak with Testcontainers, so they need Docker.
They take a couple of minutes and are end-to-end tests which are generally considered to provide better test value.

[source,bash]
----
$ ./gradlew test               # unit tests, also generates the snippets for the REST API documentation
$ ./gradlew integrationTest
$ ./gradlew build              # all of the above, plus this documentation
----

[[testing_the_api]]
== Testing the API

There are many tools out there that can be used for manual testing of the APIs, e.g. Postman (https://www.postman.com/).
The Keycloak client requires PKCE, so the tool must support it.

To use Postman, first run ``./scripts/configure-keycloak.sh``, which allows Postman's callback URL in Keycloak.
Then select ``OAuth 2.0`` as ``Auth Type`` under the ``Authorization`` tab and then select
``Authorization Code (With PKCE)`` as ``Grant type`` and ``SHA-256`` as ``Code Challenge Method``.
Enter values as follows (leave other fields empty).

|===

|Field|Value|Comment

|Callback URL|https://oauth.pstmn.io/v1/browser-callback|
|Auth URL|https://auth.fgv.local.nu:8443/auth/realms/fgv/protocol/openid-connect/auth|If ``API_KEYCLOAK_REALM`` in ``.env`` has been changed, the value must be changed accordingly
|Access Token URL|https://auth.fgv.local.nu:8443/auth/realms/fgv/protocol/openid-connect/token|If ``API_KEYCLOAK_REALM`` in ``.env`` has been changed, the value must be changed accordingly
|Client ID|spexregister|If ``API_KEYCLOAK_CLIENT_CLIENT_ID`` in ``.env`` has been changed, the value must be changed accordingly
|Client Secret|ip8dFYgp03sVytrrEeXgwHIgHAMtE350|If the secret of the client has been changed in Keycloak, the value must be changed accordingly
|Scope|offline_access|
|Client Authentication|Send as Basic Auth header|

|===

Request an access token by clicking ``Get New Access Token`` and use any of the test credentials to login.
Use the obtained access token when invoking the API endpoints.

[[mcp_server]]
== MCP server

Spexregister Server exposes an MCP (Model Context Protocol) server at ``/api/mcp`` (stateless streamable HTTP),
letting AI assistants manage spex, spex revivals, spex categories, tasks, task categories, news and tags.
Spexare and individual users are intentionally not exposed; the only user-related tool returns aggregated counts
(users per state and accounts pending approval) and requires the admin role.

Every tool call runs with the permissions of the signed-in user, and changes are recorded in the audit history
with source ``MCP``.

Authentication uses OAuth 2.0 against Keycloak with the public client ``spexregister-mcp`` (authorization code with PKCE,
redirect URIs ``http://localhost:*`` and ``http://127.0.0.1:*``). Only tokens issued to that client are accepted
by the MCP endpoint, and they are not accepted by the rest of the API.
The tokens must also have the MCP endpoint's address, i.e. ``API_BASE_URL`` with the path ``/api/mcp``, as audience.
Keycloak adds it through the client's audience mapper, which ``fgv.json`` sets from ``SPEXREGISTER_MCP_URL``.
Users confirm the access once, on Keycloak's consent page.
MCP clients discover Keycloak through the protected resource metadata at
``/.well-known/oauth-protected-resource/api/mcp``. Keycloak does not allow dynamic client registration by default,
so configure the MCP client with the client id ``spexregister-mcp``.

Locally, the MCP server is available at ``https://api.register.fgv.local.nu:8443/api/mcp``.
It can for instance be explored with the MCP Inspector (https://github.com/modelcontextprotocol/inspector).
